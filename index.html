01 / WHY SHOULD WE CARE?

私たちの日常は、
どれほど見えないインフラに依存しているのか？

動画を見る。地図を開く。ネットで買い物をする。写真を保存する。その多くは、遠く離れた場所にあるコンピューターと光ファイバー通信することで成り立っています。私たちが「クラウド」と呼ぶものは、空の上ではなく、地上にある巨大な物理設備です。

WHEN IT STOPS
サービスが止まる

決済、動画、業務システム。裏側の設備や海底ケーブルに障害が起きると、日常のサービスにも影響します。

WHERE IT RUNS
世界に分散する

企業は複数の地域に設備を配置し、応答速度の最適化や自然災害への備えを考えて運用しています。

WHO CONTROLS IT
巨大基盤が支える

多くのWebサービスやアプリは、AWSやGoogle Cloud、Cloudflareなどのインフラ上で稼働しています。

03 / NETWORK
NETWORK RELATIONSHIPS

世界は、見えない線でつながっている。

インターネットは、単一の巨大なケーブルではありません。通信事業者（ISP）や相互接続点（IX）、データセンターなどの自律したネットワーク同士が相互に接続し、光のパケットが絶えず行き交っています。

ネットワークの階層関係 / 概念モデル※ パルスは通信の流れを表す概念演出です
図の見方
丸は「ネットワークの役割」

利用者、接続事業者（ISP）、相互接続点（IX）、クラウド基盤、アプリケーションやデータを表します。

線は「論理的な接続関係」

通信は複数の組織が管理するネットワークをバケツリレーのように通過して目的地へ届きます。

経路は動的に変化する

回線の混雑や障害に応じて通信の通り道は自動的に切り替わります。経路はひとつに固定されません。

BGP / BORDER GATEWAY PROTOCOL
ネットワーク同士の道案内

自律システム（AS）と呼ばれるネットワーク群同士が、どのIPアドレスへどの経路で到達できるかを交換する仕組みです。

IX / INTERNET EXCHANGE
ネットワークの相互接続点

複数の通信事業者やクラウド事業者が直接ケーブルをつなぎ、効率よく通信を交換する物理的な拠点です。

06 / PHYSICAL ARCHITECTURE

クラウドの正体は、巨大な建物と冗長設計。

DATA CENTER
データセンター

サーバー、ストレージ、ネットワーク機器を高密度に収容し、非常用電源や大型冷却設備で24時間稼働させる物理施設。

AVAILABILITY ZONE
アベイラビリティゾーン

同じリージョン内で、電源・空調・ネットワークを物理的に分離した独立設備群。単一障害点をなくすために設計されます。

REGION
リージョン

複数のアベイラビリティゾーンを束ねた、クラウドサービスの地理的な提供エリア単位。

単一障害点を避けるための階層構造
REGION / TOKYO→ZONE A (独立電源・回線)＋ZONE B (独立電源・回線)＋ZONE C (独立電源・回線)

ひとつのリージョンの中に、物理的に離れた複数のゾーンを設けることで、ある建物で停電や機器故障が起きても、別のゾーンでシステムを継続稼働させる設計が可能になります。

KEY TAKEAWAYS（学んだこと）
  • 「クラウド」という抽象的な言葉の裏には、都市の電力網・冷却設備・海底ケーブルといった極めて物理的な制約が存在する。
  • 公開APIのステータス情報を扱う際は、取得できた事実と取得できない限界を明確に分けて表示する設計が信頼性につながる。
  • 地図上の座標プロットと回線アークは、正距円筒図法の数式とSVGのパスアニメーションを組み合わせることで、画面幅に依存せず正確に描画できる。
